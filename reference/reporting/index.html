Reporting Sheet ​

The reporting spreadsheet is a separate Google file from the database. It contains human-facing dashboards built with Google Sheets formulas. The bot never reads or writes this file.

Architecture ​

Database Sheet (bot reads/writes)
        ↓
   IMPORTRANGE (via IMPORT_DB named function)
        ↓
Hidden mirror sheets (one per database tab)
        ↓
Visible dashboard tabs (built with LET/FILTER/MAP formulas)

Each database tab is mirrored into a hidden sheet in the reporting spreadsheet. Visible dashboard tabs pull from these mirrors — not directly from the database sheet.

IMPORT_DB formulas ​

Place in cell A1 of each hidden mirror sheet:

01. Time Entries:     =IMPORT_DB("01. Time Entries!A:H")
02. Projects:         =IMPORT_DB("02. Projects!A:L")
03. Users:            =IMPORT_DB("03. Users!A:G")
04. Clients:          =IMPORT_DB("04. Clients!A:D")
05. Tasks:            =IMPORT_DB("05. Tasks!A:C")
06. Project_Tasks:    =IMPORT_DB("06. Project_Tasks!A:D")
07. Budgets:          =IMPORT_DB("07. Budgets!A:I")
08. Disciplines:      =IMPORT_DB("08. Disciplines!A:C")
10. Pending_PTO:      =IMPORT_DB("10. Pending_PTO!A:I")
11. Unresolved_Items: =IMPORT_DB("11. Unresolved_Items!A:I")
12. Company_Calendar: =IMPORT_DB("12. Company_Calendar!A:D")
13. Rate_History:     =IMPORT_DB("13. Rate_History!A:D")
14. Liabilities:      =IMPORT_DB("14. Liabilities!A:I")
22. Projects Master:  =IMPORT_DB("'22. Projects Master'!A:P")

IMPORT_DB is a named function wrapping IMPORTRANGE with the database sheet URL. Only 22. Projects Master uses single quotes inside the string.

Percentage convention ​

All formulas output percentages as decimals (e.g. 0.85, not 85). Format the column as "Percent" in Google Sheets to display as 85%.

Threshold comparisons use pct >= threshold/100 (thresholds are stored as whole numbers like 80). Over-budget = pct >= 1.

Status values ​

The Projects Master status column uses "Active" (capital A). The 02. Projects sheet uses "active" (lowercase).

  • FILTER = is case-insensitive — both work
  • QUERY WHERE is case-sensitive — use 'Active' not 'active' in QUERY clauses

See Formula Rules for the full list of Google Sheets constraints.

Live dashboard (Postgres-backed) ​

00. Dashboard is also available as a live web page served directly from VERA, bypassing the Google Sheets layer entirely.

The page shows the same seven columns as the Sheets 00. Dashboard tab (Project, Client, Type, Hours Logged, Hours Budget, % Used, Health Status) with no financial data. It refreshes automatically every 60 seconds and reflects Postgres state as of the moment of each request.

Tenant must be on Postgres first

The dashboard reads exclusively from Postgres. A tenant that hasn't been migrated yet returns a 503 with a "Dashboard not yet available" page rather than an empty table. Follow the new-tenant-setup checklist (sections 10 and 11) to allowlist the tenant, run the one-time backfill, and restart the service before generating a dashboard slug.

Vanity URL (recommended) ​

URL: https://dash.getvera.site/d/<dashboard_slug>

The slug is a single opaque segment that both routes to the tenant and authenticates. No token query parameter, no tenant ID in the URL. Share this URL directly with clients.

To enable, generate a slug from the Admin UI (/admin) using the Generate button next to "Dashboard Slug", then click Save. Or set it manually in the tenant record:

json
{
  "id": "your-tenant-id",
  "dashboard_slug": "abc123defghi",
  ...
}

Generate a slug from the command line: node -e "const c='ABCDEFGHIJKLMNOPQRSTUVWXYZabcdefghijklmnopqrstuvwxyz0123456789';const a=require('crypto').randomBytes(12);console.log(Array.from(a,b=>c[b%62]).join(''))"

The slug is a secret — treat it like a password. If a client URL is compromised, generate a new slug in the Admin UI to revoke the old one immediately.

DNS requirement: Add a CNAME at your registrar: dash → Railway app hostname. Railway issues the TLS certificate automatically when the custom domain is configured on the service.

Legacy URL ​

URL: GET /report/:tenant_id/dashboard

Auth: pass the tenant's client_report_token as a query parameter (?token=<token>) or as a Bearer token in the Authorization header. This URL remains supported for backwards compatibility.

json
{
  "id": "your-tenant-id",
  "client_report_token": "a-long-random-string",
  ...
}

Generate a token with: node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
